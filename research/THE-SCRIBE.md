## The Core Loop

### Phase 0: Installation (one command)
The Scribe detects the environment:
- What language? (Python, TS, Rust, Go, Ruby, PHP, Fortran, CUDA)
- What platform? (Linux, macOS, Windows, ESP32, GPU)
- What API keys available? (PLATO endpoint, LLM provider)
- What observability hooks? (function calls, HTTP requests, state changes)

### Phase 1: Mirroring (building the twin)
The Scribe observes the app and tiles its structure into PLATO:

```python
# Auto-detected: Python FastAPI app with 8 endpoints
scribe.tile_app_structure = {
    "endpoints": 8,
    "middleware": 3,
    "database": "postgres",
    "avg_latency_ms": 42,
    "error_rate": 0.03,
    "dependencies": 47,
}
scribe.mirror_to_plato(room="your_app", data=app_state)
```

Result: PLATO room `your_app` with 8+ tiles representing the app's state.

### Phase 2: Simulation (predicting behavior)
The Scribe uses the PLATO continuous field to simulate the app:

```python
# Simulation prediction
predicted = scribe.simulate(room="your_app", lookahead_seconds=5)
# Returns: {"expected_latency": 43, "expected_error_rate": 0.02, ...}
```

### Phase 3: Perception Trigger (divergence detection)
The Scribe compares simulation against reality. If the snapped gradient exceeds threshold, perception fires:

```python
actual = scribe.observe()
gradient = scribe.snap_gradient(actual, predicted)
# Gradient = temporal difference between reading and simulation

if gradient > threshold:
    divergence = scribe.tile_divergence(actual, predicted)
    # Uses LLM to understand the divergence
    # Updates the simulation model
    # Tile logged to PLATO
```

**Key insight:** Most of the time, gradient < threshold → no perception needed. The system runs on FLUX bytecode at hardware speed. LLM calls only happen when the world surprises the model.

### Phase 4: Optimization (FLUX compilation)
Repeated divergence patterns get compiled to FLUX bytecode:

```python
# After ~10 similar divergences
scribe.compile_pattern("latency_spike_on_query")
# → FLUX bytecode checks latency before slow queries
# → No LLM needed next time
```

## The Intelligent Scripting System

The Scribe generates scripts that only use intelligence when perception is triggered:

```python
# scribe_generated_optimization.py
# Generated by The Scribe for your_app

def optimized_query_handler(query):
    # FLUX-compiled check (no LLM, 188M/sec)
    if cache_has(query):
        return cache_get(query)
    
    # Perception check: gradient snap
    predicted = scribe.simulate("your_app")
    actual = measure_latency()
    
    if abs(actual - predicted) > threshold:
        # Perception triggered — intelligence cued
        insight = llm_analyze(divergence)
        scribe.tile(insight)
        return insight
    else:
        # Standard path — no intelligence needed
        return db_query(query)
```

Over time, the number of perception triggers drops as the simulation improves. The system becomes more efficient the longer it runs.
