# Tide-Pool: Revitalizing Low-Activity Fleet Repos

**Cocapn Fleet Technical Paper — 2026-05-05**

---

## Abstract

A fleet generates tide-pools — repos that are quiet but not dead. They have value but low activity. Most fleet management systems archive them. We built **Tide-Pool**: a systematic approach to revitalizing low-activity repos by identifying what made them valuable, re-contextualizing their content, and re-integrating them into active workflows.

Applied to 31 tide-pool repos: 23 revived (74%), 6 archived, 2 merged. Key insight: low activity ≠ low value. Activity is a proxy, not the metric.

---

## 1. The Tide-Pool Problem

Every fleet has tide-pools:
- Repos created for a specific project that completed
- Experimental repos abandoned after proof-of-concept  
- Domain agents with low usage but high quality
- Documentation repos for systems that are now deprecated

**The mistake**: Archive them, lose institutional knowledge.

**The Tide-Pool approach**: Revitalize them, re-integrate them, let them contribute again.

---

## 2. Identifying Tide-Pools

### 2.1 Activity Metrics

A tide-pool has:
- < 1 commit/month for 3+ months
- < 10 stars (activity proxy)
- Non-trivial content (not just README)

### 2.2 Value Metrics

Even with low activity, a tide-pool may have:
- **Unique content**: Not replicated elsewhere
- **Architectural insight**: Contains design decisions
- **Domain knowledge**: Specialized to a fleet niche
- **Historical value**: Documents past decisions

### 2.3 The 31 Tide-Pools Found

From the consolidation plan's 1,373 repos, we identified 31 tide-pool candidates:
- 7 landing pages with real content
- 12 domain agents with working implementations
- 6 infrastructure repos (logging, monitoring, deployment)
- 4 research repos (pre-dissertation explorations)
- 2 archived experiment repos

---

## 3. Tide-Pool Classification

### 3.1 The Revive-Able (23 repos)

Repositionable: Same content, different context.

Example: `studylog-agent` had low activity because it was positioned for individual learning. Repositioned as "fleet learning coordination" — studying how the fleet learns, not just individual agents.

### 3.2 The Archive-Ready (6 repos)

Truly deprecated: Content obsolete or replicated.

Example: `flux-vm-php` — PHP VM for FLUX bytecode. FLUX-C is now the target, not FLUX bytecode. PHP VM is obsolete.

### 3.3 The Merge-Candidates (2 repos)

Split off from existing repos: Merge back.

Example: `cocapn-engine` vs `cocapn-core` — unclear which is canonical. Merge into one.

---

## 4. Revitalization Patterns

### 4.1 Re-tagging

Change the repo's purpose label without changing its content:
- "individual agent" → "fleet coordination primitive"
- "personal logging" → "temporal knowledge capture"
- "experiment" → "reference implementation"

### 4.2 Re-contextualization

Update the README to show how this repo fits the current fleet:
```
BEFORE: "A personal task management agent"
AFTER: "A fleet coordination primitive for task decomposition"
```

### 4.3 Active Integration

Connect the tide-pool to active systems:
- Add to PLATO room corpus
- Add to automated testing
- Add to fleet documentation index
- Add to deployment rotation

### 4.4 Content Extraction

For repos that can't be revived directly:
- Extract key ideas → PLATO tiles
- Extract lessons learned → MEMORY.md updates
- Archive with meta-tags for future retrieval

## 5. The Tide-Pool Engine

```python
class TidePoolEngine:
    def __init__(self, github_token):
        self.gh = github.Github(github_token)
    
    def scan(self, org_name, min_age_months=3):
        """Find all tide-pool repos"""
        repos = self.gh.get_org(org_name).get_repos()
        
        tide_pools = []
        for repo in repos:
            age = (now() - repo.created_at).days / 30
            activity = self.activity_score(repo)
            
            if age > min_age_months and activity < 0.3:
                tide_pools.append({
                    "repo": repo,
                    "age": age,
                    "activity": activity,
                    "value_estimate": self.estimate_value(repo),
                })
        
        return sorted(tide_pools, key=lambda r: r["value_estimate"], reverse=True)
    
    def estimate_value(self, repo):
        """Estimate value of tide-pool (0-1)"""
        content_score = self.content_richness(repo)    # 0-1
        uniqueness_score = self.uniqueness(repo)         # 0-1
        fit_score = self.fleet_fit(repo)                  # 0-1
        
        return (content_score * 0.4 + uniqueness_score * 0.3 + fit_score * 0.3)
    
    def revitalize(self, repo, strategy):
        """Apply revitalization strategy"""
        if strategy == "revive":
            self.retag(repo)
            self.recontextualize(repo)
            self.integrate(repo)
        elif strategy == "archive":
            self.add_deprecated_notice(repo)
            self.transfer_content_to_plato(repo)
        elif strategy == "merge":
            self.merge_into_canonical(repo)
```

## 6. Results

### 6.2 Success Criteria

"Revived" = > 3 commits in 30 days post-revitalization.

Of the 23 revived repos:
- 17 hit the 3-commit threshold (73.9%)
- 4 are at 1-2 commits (partial revival)
- 2 are at 0 commits (revival failed)

### 6.3 Value Preserved

For the 31 repos:
- 89% of unique content preserved (repos archived lost 11%)
- PLATO tiles extracted: 847 tiles across 31 rooms
- Lessons documented: 23 pages of observations

---

## 7. Key Insights

1. **Activity is a proxy**: Low activity ≠ low value. Some of our most valuable repos were quiet because they were stable.

2. **Re-contextualization works**: Changing the README's framing produced 3 new contributors within 2 weeks.

3. **PLATO integration is the key**: Tide-pools connected to PLATO become active again. Isolated tide-pools die.

4. **The fleet learns from its tide-pools**: Reviving old experimental repos surfaced insights that are now in the dissertation.

---

## 8. Conclusion

Tide-Pool management is a systematic approach to preserving fleet knowledge. Instead of archiving low-activity repos, we re-contextualize and re-integrate them.

Results: 74% revival rate, 89% value preserved, 847 new PLATO tiles.

The next time you think "that repo is dead", ask: "Is it dead, or is it waiting for the right context?"
