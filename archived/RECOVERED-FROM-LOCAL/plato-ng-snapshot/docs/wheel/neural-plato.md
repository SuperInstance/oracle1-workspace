### 1. UltraMem TDQKR — Pure Fortran Implementation (TRANSFORMATIVE)
`sparse_memory.f90` + `tucker_decompose.f90` implement Tucker Decomposed Query-Key Retrieval (TDQKR) from the UltraMem paper (ByteDance Seed team, ICLR 2025). The algorithm:
- **Score computation**: O(n_ranks² + n_rows + n_cols) instead of O(n_rows × n_cols)
- **Implicit Value Expansion (IVE)**: 4x virtual memory expansion WITHOUT actual storage — `implicit_expand()` creates scaled linear projections from the base values
- **Top-k retrieval**: Full 2D score matrix computed via Tucker decomposition, then top-k weighted sum

**plato-ng relevance**: This is HOW you build sparse memory without Python. The Fortran is the reference implementation — translate to C and you have a pure-C sparse memory layer with TDQKR. The IVE trick alone saves 75% memory on the value table.

### 4. Negative Space — Shadow Reconstruction from Absence
`negative_space.f90` implements the **computational dual of direct reconstruction**: instead of building from what's present, carve away what's known to be absent.
- Uses Dykstra's algorithm (iterative projection onto intersecting half-spaces)
- 100 iterations max, converges when |x - x_old|² < 1e-10
- `shadow_accuracy(n_negative, n_total)`: accuracy = 1 - exp(-4.6 * density), saturating at 97.5%
- `marginal_gain(n_negative, n_total)`: which negative constraint adds the most information?

**plato-ng relevance**: This is for inference-by-elimination. When an agent knows what DIDN'T happen, negative space reconstructs what MUST have happened. This is unexplored in fleet-memory.

## Key Architectural Insight

```

```

This means ANY language can link the kernels. The mathematical core is completely language-agnostic.
